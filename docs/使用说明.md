# 使用说明

面向「想把这套装起来用」的人。设计取舍与实测数据在
[调研报告](调研报告.md)，这里只讲怎么做、出问题怎么查。

---

## 一、准备：B2 桶与密钥

### 1.1 建桶

Backblaze 控制台 → **Buckets** → *Create a Bucket*：

| 字段 | 填什么 | 说明 |
| --- | --- | --- |
| Bucket Unique Name | 例如 `my-dsh-bucket` | 全球唯一，随便起 |
| Files in Bucket are | **Private** | 私有：只有带 key 才能读。别选 Public |
| Default Encryption | Disable | 我们自己的 7z 已经加密；开了 B2 服务端加密也不冲突，只是没必要 |
| Object Lock | Disable | 不需要 |

### 1.2 建 Application Key

**Application Keys** → *Add a New Application Key*：

| 字段 | 填什么 |
| --- | --- |
| Name of Key | `dsh-remote-control` |
| Allow access to Bucket(s) | **只勾上面那个桶**（最小权限） |
| Type of Access | **Read and Write** |
| Allow List All Bucket Names | 不用勾 |
| File name prefix / Duration | 留空（不限制） |

建完**只显示一次**，记下两样：

```
keyID          = 005f0000000000000000000aa
applicationKey = K005xxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### 1.3 「云端文件名」和「加密密码」

- **云端文件名**：不是真文件，是通道的盐，**也就是「哪台电脑」的身份**。
  它在桶里的路径长这样：
  `dsh-remote-control/v2/desk-win/ch/572345c9f9f8/from-phone/0001794483231981.7z`
  （`from-phone/` = 手机写进来的，`from-desktop/` = 电脑写回去的）
  通道 ID 由 `appKey + bucket + cloudFile` 三者派生，所以**只要这一项不同，
  就是一条全新的通道**（通道 ID 与桶内前缀都不同），其余四项可以完全一样。
  也可以留空：电脑端会拿本机电脑名自动填一个（`DESKTOP-8K3F2L` → `desktop-8k3f2l`；
  中文名折不出字母，会退化成 `desk-3f9a2c` 这种短名，建议自己改成好记的）。
- **加密密码**（例如 `改成只有你知道的一句话`）：每个对象都用它做 7z 的
  AES-256 加密。**它不会上传到任何地方**，桶里只有密文。

> ⚠️ 密码丢了 = 桶里的历史消息再也解不开（本来也是设计上的「不可恢复」）。
> 密码填错不会换通道，只会报「7z 解不开：密码不对」。

### 1.4 关于 transaction 配额（重要）

B2 免费额度的 Class C 事务是**每天 2500 次**。本方案靠轮询列举来收消息：

- 空闲时每 4 秒列举一次 → 一天约 2.1 万次
- 活跃时每 500ms 列举一次 → 一天可到 17 万次

所以**长期挂着必然超额**，表现为日志里出现：

```
B2 授权失败 HTTP 403：{"code":"transaction_cap_exceeded", ...}
```

两种处理：

1. **提上限**（推荐）：控制台 → *Caps & Alerts* → 把 *Transaction Cap* 调到
   例如 50 万/天。实测 500ms 常轮询约 $0.14/天，空闲轮询约 $0.02/天。
2. **按需使用**：不看手机时点「断开」，看的时候点「重连」—— 只在开着的时段消耗。

## 二、电脑端

### 2.1 装插件

**推荐：官方安装器用 GitHub 链接装。** 设置 → 插件 → 添加，粘贴：

```
https://github.com/10jinzhi/dsh-remote-control
```

钉版本加 `#v1.0.0` 或 `#<commit-sha>`。

> 安装器把链接交给 `pnpm add`，只认「装出来的包的根 `package.json`」里的
> `dsh.bundle.patch`，**不扫描子目录**。所以仓库根就是这个插件包，
> `.../tree/main/某个子目录` 这种链接不能用。`files` 白名单保证只有
> `lib/`、`cordis.patch.yml`、`README.md` 被装进 DSH。

手动装：把仓库根的这三样拷进插件目录，或解开打好的 zip。

```bash
# 从仓库直接放
cp -r package.json cordis.patch.yml lib/ "$DSH_HOME/plugins/dsh-remote-control-desktop/"

# 或者用打好的 zip（out/dsh-remote-control-desktop-<版本>.zip）
```

> ⚠️ 不要和 `dsh-jiuling-remote-desktop` 同时启用 —— 两者都要占本地中继端口
> `17890`，后启动的那个会绑定失败。

### 2.2 填配置

重启 DSH → **设置 → DSH 远程控制**，页面里填 5 项后点 **保存并连接**。

页面里三个按钮的区别：

| 按钮 | 做什么 | 什么时候用 |
| --- | --- | --- |
| 保存并连接 | 写配置 + 让桥立即重载（不用重启 DSH） | 每次改配置 |
| **测试往返** | 真写一个加密包进桶、读回来、解密比对、删掉 | 第一次配 / 怀疑配置有问题 |
| 清空通道 | 删掉这条通道在桶里的**所有**对象 | 想彻底重来 |

「测试往返」成功的输出长这样（数字是真实测得的量级）：

```
往返正常 ✓
耗时 156ms（上传 91ms）
7z 包 266 字节，原文 138 字节
通道 daebed14ba04（指纹 4ca4a668）
测试对象已删除
```

失败时它会明确告诉你是哪一步断的：

| 报错 | 原因 |
| --- | --- |
| `授权失败 HTTP 401` | keyID / applicationKey 不成对，或 key 被删了 |
| `授权失败 HTTP 403 transaction_cap_exceeded` | 超额了，见 1.4 |
| `账号下找不到 bucket「xxx」` | 桶名拼错，或 key 被限定到了别的桶 |
| `上传返回成功，但桶里列举不到` | key 没有写权限 |
| `对象列举得到但下载不回来` | 桶是 Private 但 key 没有读权限 |
| `7z 解不开：密码不对…` | 密码打错了 |

### 2.3 配置文件在哪

```
$DSH_HOME/dsh-remote-control/config.json      # 5 项配置，权限 0600
$DSH_HOME/dsh-remote-control/state.json       # 两个游标（outSeq / inCursor）
```

也可以用环境变量覆盖（优先级更高，适合放到启动脚本里）：

```bash
DSH_REMOTE_KEY_ID=... \
DSH_REMOTE_APP_KEY=... \
DSH_REMOTE_BUCKET=... \
DSH_REMOTE_CLOUD_FILE=dsh-remote-control \
DSH_REMOTE_PASSWORD='...' \
dsh
```

改了环境变量要重启 DSH；改 `config.json` 不用（桥看 mtime 自动重载）。

## 三、手机端

### 3.1 安装

```bash
adb install -r out/dsh-remote-control-1.0.0.apk
```

也可以把 APK 拷到手机上点开装（需要在系统里允许「安装未知来源应用」）。

**签名说明**：这个包是用本仓库 `out/dsh-remote.keystore` 自签的
（第一次构建时自动生成，密码 `dsh-remote-local`）。

> keystore 的**文件名**仍叫 `dsh-remote.keystore`，不跟产品名走：它是签名身份的
> 落盘位置，改了名会让已有构建找不到旧密钥，一不留神就重新生成一份、签名随之改变，
> 已装的 APK 必须先卸载再装。里面的**条目名**是 `dsh-remote-control`，与构建脚本
> 的 `--ks-key-alias` 配套；两者一起改才有意义（改条目名可用
> `keytool -changealias`，密钥与证书指纹都不变）。

所以：

- 换一台机器重新构建，签名会变 → 需要先卸载再装；
- 想长期用同一签名，把 `out/dsh-remote.keystore` 备份好。

### 3.2 连接

打开应用 → 填**和电脑端一模一样**的 5 项 → **保存并连接**。

顶栏那个圆点就是状态：

| 颜色 | 含义 |
| --- | --- |
| 灰 | 还没连上（配置不全 / 链路未启动） |
| 黄 | 链路在跑，但电脑还没回应（电脑端插件没装？桥没起来？） |
| 绿 | 已连上电脑 |
| 红 | 出错了，下面的「状态」卡里有具体错误 |

状态卡里的**指纹**（8 位十六进制）应当与电脑端设置页显示的一致 ——
不一致说明五项里有不一样的（最常见是「云端文件名」多了个空格）。

### 3.3 一台手机连多台电脑

手机端的配置是**可以有多份**的：最上面那张「电脑」卡片就是一个档案列表。

- **新增**：点「＋ 新增」→ 起个名字（例如「书房台式机」）→ 表单清空，
  但**「云端文件名」已经按这个名字预填好了**（中文名会变成 `desk-3f9a2c`
  这类短名，可按那台电脑的机器名改成 `desk-win` 之类）→ 填其余 4 项 → 保存
- **切换**：下拉里选另一台。切换会**拆掉旧链路再建新的**，所以不会出现两台电脑
  的消息混在一个会话列表里
- **重命名 / 删除**：删除要点两次（第二次是「确认删除？」），删掉会连它的密码一起清掉
- 每台电脑**各有自己的收发游标**：从台式机切到笔记本，不会把台式机「读到哪了」
  带过去，也不会重复收消息

⚠️ **两台电脑不能共用同一个「云端文件名」**。共用的话它们会抢同一条 `from-phone/` 队列 ——
谁先轮询谁拿走，消息就随机落到其中一台。反过来说，**只要这一项不同就够了**，
其余四项两台电脑完全可以一样。区分方式按省事程度排：

| 做法 | 怎么配 | 适合 |
| --- | --- | --- |
| 云端文件名不同 | 两台填同一个桶、同一把 key，`cloudFile` 分别写 `desk-win` / `mac-mini` | 最省事；但一把 key 泄露，所有电脑都能被写 |
| 每台一把 key | B2 里给每台单独建 key（都限定同一个桶）+ 各自的 `cloudFile` | **推荐**：通道天然不同，泄露一台不牵连另一台 |
| 每台一个桶 | 完全隔离 | 隔离最强，但要管多个桶和配额 |

电脑端**不需要任何改动**：每台电脑本来就各存各的 5 项，三台就是三个独立的桥。

### 3.4 日常使用

- **齿轮（右上角）**：工作区/对话列表，可刷新、可在某个工作区开新对话
- **点会话**：拉一页历史（30 条气泡）+ 订阅实时事件
- **底部输入框**：回车发送（Shift+回车换行）；电脑处理中会变成「停止」
- **审批弹层**：电脑要执行命令时弹出，选项按电脑端给的来（允许一次 / 拒绝…）
- **返回键**：会话页 → 列表页 → 退出，逐级退

## 四、从源码构建 APK

### 4.1 工具链

只需要两样东西，解压到仓库根的 `_toolchain/`：

```
_toolchain/
  android-14/        # build-tools 34（aapt2 / zipalign / dexdump + lib/d8.jar、lib/apksigner.jar）
  android-35/
    android.jar      # platform 35 的 android.jar
```

来源：Android SDK 的 `build-tools;34.0.0` 与 `platforms;android-35`。
`_toolchain/` 已在 `.gitignore` 里（约 100MB）。

JDK 17 会被自动找到：`JAVA_HOME` → `~/.jdks/*` → IntelliJ IDEA 自带 JBR。

### 4.2 构建

```bash
node tools/build-apk.mjs
```

```
  aapt2 compile … ok (48ms)  5.0KB
  aapt2 link … ok (128ms)  14.1KB
  javac … ok (1940ms)  25 个源文件 → 54 个 class
  d8 … ok (2505ms)  91.7KB
  jar uf classes.dex … ok (314ms)  62.5KB
  zipalign … ok (92ms)  4 字节对齐
  keytool（首次生成调试证书） … ok (950ms)
  apksigner sign … ok (706ms)

== 产物 ==
  文件       out/dsh-remote-control-1.0.0.apk
  大小       72.7KB
  SDK        26 / 34
  SHA-256    f692cb3b…
```

构建报告（每一步耗时、SHA-256、签名 DN）落在 `android/build/build-report.json`。

### 4.3 构建脚本里两个「反常识」的点

1. **所有原生工具都用相对路径 + `cwd=项目根`**。`aapt2`/`zipalign` 是原生 exe，
   走系统 ANSI 代码页；仓库路径里有中文时，绝对路径会直接
   `failed to open directory`。
2. **d8 / apksigner 走 `java -cp/lib/*.jar`，不调 `.bat`**。Node 20+ 不允许
   `execFile` 一个 `.bat`（`EINVAL`），而 `cmd /c` 又会把中文路径再折腾一遍。

## 五、排障

### 5.1 电脑端

| 现象 | 查什么 |
| --- | --- |
| 设置页显示「通道未运行」 | 5 项是否填全；`$DSH_HOME/dsh-remote-control/config.json` 是否存在 |
| 日志里有「7z 缺失」 | 装 7-Zip，或设 `DSH_REMOTE_7Z` |
| 「订阅出错」 | 中继端口被别的插件占了（关掉另一个 remote 插件） |
| 「N 个对象解不开（密码不一致？）」 | 手机和电脑的密码不一样。**坏帧不会被删**，可在桶里人工取回 |

### 5.2 手机端

| 现象 | 查什么 |
| --- | --- |
| 状态灯一直黄 | 电脑端桥没跑（DSH 没开 / 插件没装 / 配置没填）；或两端通道 ID 不同 |
| 「B2 授权失败 401」 | keyID/applicationKey 打错（注意前后空格） |
| 「7z 解不开：密码不对」 | 密码不一致 —— 但配对信息是对的（通道能通，才轮得到解密） |
| 「电脑没有回应」 | 电脑端 `from-desktop/` 没在写；看电脑端日志有没有「轮询出错」 |
| 点发送一直不转 | 电脑端会话可能已经结束，重开一次会话 |

### 5.3 想看桶里到底有什么

任何一台装了 7-Zip 的机器都能人工取回并解开（这也是选标准 7z 的好处）：

```bash
# 列举（用 b2 CLI 或控制台都行）
b2 ls --long --recursive b2://<bucket>/dsh-remote-control/v2/<云端文件名>/

# 取一个对象下来，用密码解开
b2 file download b2://<bucket>/dsh-remote-control/.../from-phone/0001794483231981.7z ./m.7z
7z e -so -p'<密码>' ./m.7z | python -m json.tool
```

## 六、卸载 / 重置

| 想做什么 | 怎么做 |
| --- | --- |
| 换一台手机 | 新手机填同样 5 项即可（通道是算出来的，不绑定设备） |
| 彻底清空历史 | 电脑端设置页 → **清空通道**；或删掉桶里 `dsh-remote-control/v2/<云端文件名>/` 整个前缀 |
| 换通道 | 改「云端文件名」→ 两端都改 → 旧对象留在旧前缀下（可手动删） |
| 停掉手机轮询 | 应用里点「断开」（前台服务仍在，只是不再轮询） |
| 完全卸载电脑端 | 停插件、删 `$DSH_HOME/dsh-remote-control/` |
